# 2026.11.24 改动：技能路由与运行时摘要同步

以远程 `main` 的 `ea08730` 为比较基线，承接已合并的 #6。本次同步工作区现有技能和运行时计算改动，结合 Gemini／Antigravity 的诊断与复测记录说明原因，并独立复核发布版本。

1、
改动：将 7 个 Skill 的说明统一为“负责／不负责”，完整任务使用按优先级匹配的互斥决策树；普通规划、同机多步和复杂任务图各读所需参考页。
原因：原文档存在重复规则和多入口耦合，模型容易重复读取、来回换路由。
影响：`AGENTS.md` 从 7,330 降至 3,759 字节，7 个 Skill 正文合计从 34,196 降至 19,418 字节；保留按需查表、参数及诊断参考页。这是文件大小变化，不等同于固定的 token 节省比例。

2、
改动：同步静态运行模式 `MODE = PLANNING_ONLY`，默认完成查询、规划、校验和交付；禁止自检、环境扫描及无效在线提交调用，保留 `ONLINE_EXEC` 的文档路由。
原因：Gemini 复盘发现测试环境未部署中央入口时，模型仍尝试提交，再扫描环境查找路径，产生确定性失败和额外上下文。
影响：当前规划任务直接交付“方案已生成并检查，尚未下发”。该模式是系统提示约定，不是新增的命令行参数或运行时强制拦截；中央授权与提交实现没有在本次改写。

3、
改动：补齐 `constraints`、`required_drones`、`places`、`track`、`scan`、`transit` 的类型和示例，明确动态位置、默认圆形范围及任务失败后的处理方式。
原因：历史轨迹出现约束格式错误、把纯飞往改成搜索、未指定载荷却自行限制激光雷达、对同一动态语义反复构图等问题。
影响：保留用户原始动作、载荷和归属要求；未点名时自动选机，动态部分保留待补项；独立子任务可继续，整体组装失败时不得伪造完整交付文件。

4、
改动：候选摘要增加前 15 架 `candidates_top` 和全量 `reachable_lb_count`，包含载荷、续航、电量、距离、飞行半径与预算；成本筛选摘要增加最多 15 个 `retained_uav_ids`。
原因：只返回候选数量时，模型为推荐替代机反复拆读大产物，还可能把明显不可达的机号写入建议。
影响：有中心坐标时按半径及往返航程下界、距离排序，数量仍按完整候选集统计。`reachable_lb` 未核验区域作业量、完整时间和障碍，仅用于初筛，不是完整任务可行性证明。

5、
改动：流水线失败时附带 `last_ok_step` 与 `last_ok_summary`，保留失败状态、诊断字段和已经完成的步骤。
原因：末段动作组装失败后，模型缺少前一步航迹摘要，容易重新读取或修改上游产物再试。
影响：可以直接区分已计算部分和失败环节；失败仍停止依赖链，前一步成功不能冒充整任务通过。

6、
改动：任务图摘要增加分支 `task_key`、汇总 `task_keys`，保留候选筛选机号；超过 3 个分支时对重复的分配、告警和待补项使用 `same_*_as` 引用。
原因：历史多分支输出重复过多，容易截断；缺少任务编号又迫使模型重读完整产物。
影响：缩短工具回传，同时保留每个分支身份、触发条件及独有告警。完整分支仍保存在产物中，引用相同证据不代表删除该分支；任务图仍只规划、不下发。

7、
改动：区域预览在大航点数组前输出 `path_length` 和新增的 `waypoint_count`。
原因：大区域航点很多，工具输出截断时，原来位于数组后面的距离字段可能不可见。
影响：模型可先读路线长度和点数，减少为取一个数值而拆读大文件；不改变路线几何，也不将覆盖预览视作覆盖完成或避障验证。

8、
改动：将 `fleet_dispatch.py`、`apply_zone_alloc.py`、`start_target_tracking.py` 从活动技能脚本目录迁至 `uav_runtime/_deprecated/`；补充 7 项摘要契约回归测试。
原因：旧的直接下发、区域分配及目标跟踪入口会与现行中央控制流程冲突，新增摘要字段也需要独立回归。
影响：保留旧文件便于追溯，活动文档和脚本使用现行入口；测试覆盖候选排序与全量计数、失败证据保留、多分支告警还原，以及大航迹的摘要字段顺序。

本次未引入完整覆盖执行、螺旋扫描、纯转场提交或异地落地等新能力；相关能力边界仍以技能契约和实际工具返回为准。
