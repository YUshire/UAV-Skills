# 任务入口与编排

## 意图与边界

结合整句及上下文识别动作、对象、地点、执行机与数量、顺序、条件、时限和结束动作，保留用户明确要求。已有信息直接沿用，能查库补齐的先查；只询问仍缺且阻塞任务的必要事实。单项请求直接读对应技能，不强制走完整链路。

“派……”“去……”“巡逻……”等明确动作指令即本次执行授权；“只规划”“先给方案”“确认后执行”等限定优先。原方案满足要求且环境具备时，连续规划、校验、下发，不重复询问是否执行。改变明确约束的备选须说明差异并取得接受，离线方案也不能静默采用；减少点名机、共担改单机同样属于变更。

机号须区分执行机与位置参照机；点名参与机及恰好出动数量必须保留，共担可行性还须核对等待预算。候选与约束细则见普通规划页，失败解释统一见阶段诊断。

执行请求直接进行所需查询、规划和校验，不以额外环境自检作为前置步骤；实际工具调用报告配置或组件缺失时，完成可支持的部分，如实说明未下发。只规划和待确认方案不启动感知或下发。确认仅对应最近待确认方案；修改后旧方案作废，恢复失败才重新规划。故障补做沿原任务授权按运行控制流程处理。

## 按场景阅读

先选择本次命中的入口，再在需要某项输入、接口或失败诊断时读对应说明；不预读全部参考页，已读内容直接复用。

| 遇到什么情况 | 再读什么 |
|---|---|
| 普通完整搜索/探索/巡逻规划 | [artifact-pipeline.md](references/artifact-pipeline.md)：意图细则、默认值、候选与区域、普通计算链；有缺项时再读对应能力技能 |
| 同机多步骤、search/patrol 混合动作 | [combined-tasks.md](references/combined-tasks.md)：每步参数、顺序与能力核对；普通计算复用 artifact-pipeline |
| 跨机依赖、条件分支、动态位置，或独立扫描/录像/拍照/观察/模式切换、自定义时长 | [task-graphs.md](references/task-graphs.md)：节点、依赖、运行时引用与条件方案；该入口只规划 |
| 完整方案或确认卡准备交付 | [plan-delivery.md](references/plan-delivery.md)：交付字段、状态边界与确认卡；动作展示复用 flight-control 的开关规范 |
| 确认、修改、取消待确认方案，或普通方案已授权准备下发 | [flight-control/SKILL.md](../flight-control/SKILL.md)：确认回复处理、就绪检查与中央下发 |
| 运行指令、任务事件、进度或原因查询 | [runtime-control.md](../flight-control/references/runtime-control.md)：查询、版本与幂等、待决策和异常补做；仅问原因不授权重新起飞 |
| 候选、成本、分配、航迹或组装失败 | [diagnostics.md](references/diagnostics.md)：只读对应阶段，集中解释速度、航高、航程及工具失败 |

普通搜索/巡逻附带目标检测或中央策略跟踪，且没有独立接口步骤时，仍走普通链路；动作数组没有 track 不代表漏跟踪。扫描对象与检测目标分开；有独立接口步骤或逐目标条件要求时走任务图，不来回改目标清单。

“找到后以它为中心……”保留真实发现位置的运行时引用，不要求用户预先给出未来坐标，也不用原区域中心代替。明确“先……再……”和跨机“完成后”保留依赖；只允许无依赖步骤并行。

## 结果状态与交付

按真实证据区分已查询、已生成几何方案、动作已检查、已提交、正在执行和已完成；部分成功不能称整任务完成。任务图须看 planning_status、分支 violations/pending，外层 OK 只表示工具正常返回；已知前段不能直接当完整任务下发。

用日常中文先说结果、安排及未完成部分，数值采用本次工具结果并保留单位与范围。动作展示读取本次 assemble_plan 返回的 summary.show_actions，遵循 flight-control 的唯一布尔开关；不因精简入口改变展示行为。必需内容自足，不用“同上”或文字占位代替动作 JSON。失败后停止依赖步骤，按阶段诊断交付，不重读源码或重复计算补证据。
