# 完整方案交付模板与核对清单（严格写死格式，禁止自由发挥）

> **强制格式铁律**：所有规划交付、备选确认与能力拦截回复，**必须 100% 严格按本页对应的固定 Markdown 模板（模板 A / 模板 B / 模板 C）输出**——保留固定 Markdown 标题（`###`）、加粗字段、Markdown 表格与 ` ```json ` 代码块结构。**严禁自由发挥排版、严禁退化为无格式纯文本、严禁增删固定模块。**

## 交付前 4 项快速核对（核对 1 次直接回复，不重复规划）

1. **数值、距离与告警依据**：
   - 直接采用 `summary` 返回值（`estimated_range_m`、`estimated_battery_after`、`takeoff_to_jobs_m`、`reserved_airborne_time_s`、`max_distance_m`）；**严禁**用局部坐标 X/Y 单轴分量心算直线距离，严禁跨机/跨区张冠李戴。
   - 展示预计航程或电量时，紧邻注明统计范围（采用 `summary.budget_scope`；仅用户明确要求盘旋/悬停/待命的单程任务注明“按单程计算，不返航，结束后原地悬停”，未指定时默认往返并注明“往返”）。
   - 任务图分支的 `violations` / `pending` 告警（特别是 `TIME_RESERVATION` 超预算）必须如实告知；部分失败时开头说明已完成与受阻范围，后续执行条件须保留未解决项。
2. **交付请求 JSON（仅当普通任务 `assemble_plan` 校验通过 `artifact_created=true` 时写入）**：
   - 使用 `write_file` 保存至 `artifacts/requests/delivery_<task_key>.json`（勿把 pipeline 输入文件当作交付请求 JSON；**`assemble_plan` 整体失败或能力超界拦截时禁止写该文件，严禁篡改上游 `build` 产物跑子集**）：
   ```json
   {
     "task_key": "<summary.task_key>",
     "artifact_file": "<assemble_plan返回的artifact_file>",
     "participants": ["UAV-003"],
     "targets": [],
     "policies": {"land_on_return": true}
   }
   ```
   - **未指定结束动作时默认写 `{"land_on_return": true}`（返航降落）**；仅当用户明确要求盘旋/悬停/待命/不返航时写 `{"land_on_return": false, "on_search_complete": "HOLD"}`。
   - 要求发现后跟踪：在 `policies` 加 `"on_first_confirmed": "APPROACH_AND_TRACK", "tracking_target_ids": ["<target_id>"]`，并说明 approach/tracking profile 待执行提交时按 `status` 补齐。
   - 复杂任务图保留原图 JSON 即可；纯“只回答可行性”咨询或能力超界拦截不写交付请求 JSON。
3. **动作 JSON 强制展示规则（只要做出了规划就必须展示）**：
   - **必展条件**：除非本次任务属于**能力超界拦截（模板 B）**、完全无法规划（`INFEASIBLE`/`BLOCKED`）或工具报错，否则**但凡做出了规划**（无论是直接满足原意图，还是在能力边界内因预算/机型受限给出备选方案待用户确认，无论是普通 `--pipeline` 还是复杂任务图 `plan_task_graph`），只要工具返回了 `summary.participants[*].actions` 或 `summary.scenarios[*].assignments[*].actions` 且 `summary.show_actions` 不为 `false`（当前默认 `true`），回复中**必须**在 `### 动作序列` 下用合法 ` ```json ` 代码块逐机完整展示动作序列（保留 `count/first/last` 折叠，**严禁遗漏、严禁用文字概括替代、严禁用“同上”“其余类似”、省略号或注释**，不混入已放弃版本）。
   - **禁止展示条件**：能力超界拦截（模板 B）、完全无法规划/报错、纯可行性咨询未生成规划，或 `summary.show_actions` 显式为 `false` 时，不展示动作序列，严禁凭空手写动作。
4. **日常中文与状态边界**：
   - 禁用内部术语（`dry-run`、`离线校验`、`本地校验`、`mock`、`submitted=false`、`中央下发通道`、`任务入口`、`规划工具`、脚本与产物绝对路径）；下发状态一律以实际工具返回为准（未提交时写“方案已生成并检查，尚未下发”，能力超界拦截写“任务无法下发（当前能力不足）”），并注明“路线尚未核对现场障碍”（带目标时另注“目标配置已检查，实际识别能力尚未验证”）。
